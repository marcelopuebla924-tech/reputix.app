## Scope
Read-only inspection of effective table/view privileges, RLS state, view definitions, function security attributes, and Supabase Security Advisor findings. No production SQL mutations, data changes, auth changes, deployment, or secret access were performed.

## Confirmed findings
1. All 20 public base tables inspected have RLS enabled. Four tables have RLS enabled without policies: `business_monthly_history`, `business_verification_documents`, `payment_events`, and `review_ai_moderation`. Their current grants do not provide anon/authenticated SELECT or write access in the privilege audit; keep them inaccessible to client roles unless a deliberately scoped use case is designed.
2. Supabase Security Advisor reports two SECURITY DEFINER views:
   - `public.owner_business_dashboard`
   - `public.owner_business_hourly_patterns`
   Both are owned by postgres and have no `security_invoker=true` reloption. Both definitions explicitly filter on `auth.uid()`, verified owner claim, approved business, and an active paid subscription; the hourly view additionally requires Pro and at least three reviews per hour. Grants are authenticated SELECT only; anon has no SELECT.
3. Security Advisor reports `public.submit_business_proposal(...)` is SECURITY DEFINER and executable by anon and authenticated. The inspected body validates required fields/lengths, rejects duplicates, and inserts only pending proposals. Its search_path is empty and object references are schema-qualified. This appears intentionally public, but keep rate limiting/abuse controls in the review checklist.
4. `public.owner_respond_to_complaint(uuid,text)` is SECURITY DEFINER, executable by authenticated only, validates auth.uid(), response length, and verified ownership. Its configured search_path is `public`; recommend hardening to an empty search_path with schema-qualified references in a reviewed migration.
5. `public.reputix_publish_valid_reviews()` is SECURITY DEFINER, not executable by anon/authenticated, and configured with search_path public. It is run by the existing production cron job. Do not alter cron or production function in this audit.
6. `public.is_reputix_admin()` is SECURITY INVOKER, stable, search_path empty, and callable by anon/authenticated; it returns a boolean based on JWT app_metadata role. No issue identified from this definition alone.
7. Broad SQL grants exist on several RLS-protected tables (for example business_photos, business_promotions, businesses, reviews, user_profiles, user_publications, business_owner_claims). SQL grants do not bypass RLS, but staging must not blindly reproduce these grants. Validate effective access with disposable identities and RLS policies before deciding the minimum grants.
