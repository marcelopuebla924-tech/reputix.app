## Routine security review
Reviewed full definitions and ACLs for all five public routines.

### `is_reputix_admin()`
- SECURITY INVOKER; empty search_path.
- Uses JWT app_metadata `reputix_role=admin`.
- EXECUTE currently granted to anon, authenticated, service_role, postgres. Function only reads claim and returns boolean.

### `owner_respond_to_complaint(uuid,text)`
- SECURITY DEFINER; search_path set to public.
- EXECUTE authenticated/service_role/postgres; not anon.
- Checks auth.uid(), response length (3–3000), and verified owner claim; update target and relation are schema-qualified.
- Hardening candidate for staging: use empty search_path and schema-qualify auth function references; test exact behavior before any migration.

### `refresh_business_monthly_history(date)`
- SECURITY INVOKER; empty search_path.
- EXECUTE only postgres/service_role.
- Uses schema-qualified tables and aggregates published reviews for a month.

### `reputix_publish_valid_reviews()`
- SECURITY DEFINER; search_path set to public.
- EXECUTE only postgres/service_role.
- Publishes pending reviews older than 24 hours for approved businesses when at least one comment/score is present and all supplied scores are 1–5.
- Hardening candidate for staging: empty search_path plus fully qualified built-ins; scheduled job must remain isolated from disposable staging data.

### `submit_business_proposal(...) RETURNS uuid`
- SECURITY DEFINER; empty search_path.
- EXECUTE granted to PUBLIC, anon, authenticated, service_role, postgres.
- Uses pg_catalog-qualified trim/length functions and schema-qualified public.businesses; validates required fields and lengths, blocks matching pending/approved proposals, inserts pending proposal.
- Public execution is intentional for anonymous business submissions but must be stress-tested for abuse/rate limits and duplicate race handling.
